# 手动安装（文件复制方式）

本页描述不运行 `install.ps1` 的文件复制安装。PowerShell 脚本安装见 [README](../README.md#方式二powershell-自动化脚本安装推荐)：脚本额外提供哈希校验、安装清单、备份和失败回滚；手动方式需要自己记录复制的文件。Steam 工坊订阅仅下载内容，不能自动部署原生加载器。

## 1. 下载并检查目标

从 [Releases](https://github.com/boyl/astral-forge/releases) 下载 `aamod-0.1.9-dev-runtime.zip`，解压到单独目录；工坊下载的同名压缩包也可使用。不要把整个压缩包直接解压进游戏目录。

关闭游戏。通过 Steam 的「属性 → 已安装文件 → 浏览」打开游戏目录，确认里面有 `Astral Ascent.exe`。已验证范围为 Steam Windows x64 2.6.4 单人，运行机器需要对应的 x64 Visual C++ 运行库。

如果目标目录已有 `winmm.dll`、`winmmHooked.dll` 或 `aamod_core.dll`，先核实来源，不覆盖未知文件。已有 `aamod/install.json` 表明框架由脚本管理，应先按原脚本卸载。不同 Mod 的同名加载入口不能直接叠加。

## 2. 复制三个加载文件

| 来源 | 目标：与游戏 EXE 同级 |
| --- | --- |
| 运行包 `out/winmm.dll` | `winmm.dll` |
| 运行包 `out/aamod_core.dll` | `aamod_core.dll` |
| 本机 `%WINDIR%\System32\winmm.dll` | **`winmmHooked.dll`** |

使用文件资源管理器打开 `%WINDIR%\System32`，复制其中的 `winmm.dll` 到游戏目录，并把这份副本重命名为 `winmmHooked.dll`。如果复制时提示覆盖已有 `winmm.dll`，取消操作；可以先把系统 DLL 复制到单独的临时目录、重命名，再移入游戏目录。不要改名或移动系统目录中的原文件。

必须使用本机 System32 的 **64 位** DLL，不使用 SysWOW64 的 32 位文件，也不从其他电脑下载系统 DLL。运行包不包含该系统文件。

保留 BD Mod 的 `version.dll` 及其目录。默认安装不复制 `out/d3d11.dll` 或同时启用第二个加载入口。

最小结果：

```text
Astral Ascent/
├─ Astral Ascent.exe        （已有游戏文件）
├─ winmm.dll               （框架加载入口）
├─ winmmHooked.dll         （本机系统 DLL 的副本）
└─ aamod_core.dll          （框架核心）
```

## 3. 安装所需插件

仅复制自己需要的插件到 `aamod/mods/<插件目录>`。插件目录至少包含 `mod.json` 和清单中 `entry` 指定的 DLL；有资源时一并复制 `assets`。仅加载可信的原生 DLL。

例如运行包内的构筑示例：

```text
Astral Ascent/aamod/mods/build_selector/
├─ mod.json
└─ build_selector.dll
```

在这个安装副本的 `mod.json` 中把 `enabled` 改为 `true` 才启用该示例。不要一次启用所有示例；有些示例会修改玩法，部分仅用于开发验收。

基础安装可从 Steam 正常启动。构筑示例需要受控命令；事件响应示例还需要原生事件。安装方式与启动方式相互独立，手动复制后也可使用运行包里的启动脚本：

```powershell
# 在运行包解压目录执行；需要 PowerShell 7。
./tools/launch-game.ps1 -GameDir '<游戏目录>' -Commands
# 需要原生事件的插件：
./tools/launch-game.ps1 -GameDir '<游戏目录>' -Commands -GameplayEvents
```

开关仅作用于这次启动，不会因为手动安装而默认开启。两个完整示例及 F10 菜单说明见 [内容开发者快速开始](内容开发者快速开始.md)。

## 4. 检查加载

首次启动会创建默认数据目录及配置。通常检查 `aamod/logs/aamod.log`，确认版本和 `aamod core ready`；游戏目录不可写时，默认数据可能转到 `%LOCALAPPDATA%\aamod`，详见日志和 [SUPPORT](../SUPPORT.md)。

能打开游戏不等于插件已加载；同时核对日志中的插件加载结果。默认不启用渲染回调，无需用 d3d11 入口才能使用构筑菜单。

## 5. 手动更新、卸载与改用脚本

手动安装不生成 `aamod/install.json`，`install.ps1 -Uninstall` 无法识别这次安装。保留本次来源和文件清单，关闭游戏后，只移除确认属于本次手动安装的 `winmm.dll`、`winmmHooked.dll`、`aamod_core.dll`；不要删除 Windows 系统文件、BD 的 `version.dll`、游戏原文件或存档。

更新时先核实旧文件属于自己的手动安装，再替换为新运行包的相应文件，并查阅版本兼容说明。保留 `aamod` 中自己的插件、配置、日志和 `plugin-data`，避免覆盖已有预设。

改用自动化脚本安装时，先完成上述手动卸载，再运行安装器。反过来，从脚本方式改为手动方式，应先执行原脚本的卸载命令，再按本页复制。不要伪造安装清单或强制覆盖未知文件。
