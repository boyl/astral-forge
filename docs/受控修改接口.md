# 受控修改接口（实验入口）

公共 C ABI 已追加插件命令 token、提交和结果查询。当前只实现恢复玩家血量的最小命令，仍属实验入口：默认不执行且不报告 `AAMOD_CAP_COMMANDS`。使用公共 `tools/launch-game.ps1 -Commands` 后，子进程设置 `AAMOD_EXPERIMENTAL_COMMANDS=1`，已验证适配器才启用消费并报告能力位；未知 EXE 指纹始终禁用。回血示例本身仍默认关闭。

请求包含完整结构大小、命令种类、P1/P2 编号、预期场景 epoch 和有限正数恢复量。全局最多 64 条待执行请求，128 条结果记录；满队列、非法参数、失效插件 token 或已过期结果均返回明确错误。提交成功只表示入队。结果包含执行状态、执行前后血量和游戏更新线程 ID，插件可重复查询但不会重复执行命令。

核心在经过验证的游戏 post-update 边界按请求 ID 顺序消费。目标 epoch 不匹配、玩家未出现、血量字段不可用、零或负血量、当前血量超过最大值、非大厅或游戏 layout 均不修改。成功操作仅恢复当前血量，并限制到当时最大血量，不改最大血量、不复活、不写玩家位置或直接覆盖存档。游戏可以在后续正常保存流程持久化其状态，玩法作者必须考虑这一副作用。

插件初始化阶段可以入队，但核心在初始化成功后才激活其 token。失败时取消；插件卸载前撤销 token，拒绝新请求并取消未执行命令。核心停止或适配器故障也取消待执行请求。API 不保存插件函数或游戏对象指针；token 不是安全沙箱，同进程原生插件仍需要信任。

`mods/heal_once` 为仅使用公共 SDK 的示例，默认关闭。每个场景首次受伤后提交一次恢复请求，再提交一个不匹配 epoch 的请求用于核对拒绝行为。离线测试验证激活门禁、归属、顺序、限幅、P1/P2、死亡拒绝、过期场景、队列满、写失败、重复查询、结果淘汰和停止取消。

2026-10-03 的最终 0.1.5-dev 隔离实机通过 P1 战斗回血与过期请求拒绝：正常菜单、索瓦开局和两个传送房间后，敌人攻击将当前血量降到 423，上限 447；公开 SDK 命令在原生更新线程恢复至 447，上限保持 447。独立只读原生观察、state_watch、状态事件及 HUD 截图相互印证；故意不匹配 epoch 的请求返回状态 2。此前未完成的路线保留为历史失败记录。

本轮只有单人、一个战斗房间、一次恢复和一次过期拒绝的实机证据，不能据此宣称双人、全地图、长时间循环和所有拒绝路径已实机覆盖。实验门禁与默认关闭保持不变；其余失败路径目前依赖离线契约。

0.1.7-dev 的 600 秒隔离运行中，正常输入进入战斗后，SDK 请求将 399/447 恢复至 447/447，命令结果、状态事件和 state_watch 一致，过期 epoch 请求拒绝。两秒间隔的独立原生采样错过瞬时满血，随后观察到再次受击后的 408/447，不把该采样算作满血证据。
