# 状态事件接口

追加 `AAModAPI.state_events`，原 ABI 1 前缀不变。新能力位为 `AAMOD_CAP_STATE_EVENTS`；原先预留的 `event_subscribe` 仍未实现。事件来自精确游戏适配器发布的快照差分，不是原生受伤、击杀、拾取通知。

每条记录包含单调递增 ID、变化标志和完整快照。状态、引擎场景及 epoch、玩家出现/消失、字段可用性、当前或最大血量变化可以合并在同一条记录中。仅坐标变化不产生记录。血量为零不等于已捕获原生死亡事件；玩家对象可以继续存在于结算期间。

插件用自己的游标轮询，记录按 ID 递增返回。没有核心调用插件的回调，也没有订阅资源，因此插件关闭时只需停止自己的轮询线程。生产快照和事件写入共用锁，查询从任意线程复制数据，不返回游戏或插件指针。独立示例见 `mods/event_watch`。

缓冲区保留最近 128 条记录。`after=0` 从当前保留的最旧记录开始；成功后用最后一条 ID 更新游标，不用 `newest` 跳过尚未读取的记录。容量为零且事件指针为空时可以查询最新 ID。游标过期或超过最新 ID 时返回 `AAMOD_ERR_EVENT_CURSOR`，数量为零并返回当前最新 ID；插件须显式记录丢失，再选择从最新 ID 恢复或重新读取保留历史。事件大小必须精确匹配当前结构，非法参数不写输出。

未知游戏版本仍可读取适配器的不可用状态记录，不会得到伪造的游戏事件。故障和停止记录携带清空后的快照。事件 ID 在当前核心生命周期内持续递增；核心卸载后不能继续使用旧 API 或游标。

离线验证覆盖多游标重复读取、事件合并、血量归零但玩家仍存在、坐标过滤、同 layout 的 epoch 改变、环形缓冲溢出、未来游标及无效缓冲区。实机状态事件的验证与只读快照验收分别记录。
