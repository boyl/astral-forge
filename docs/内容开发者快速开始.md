# 内容开发者快速开始

Astral Forge 提供可复用的加载器、版本化 C ABI、游戏适配与命令结果。开发者负责自己的玩法规则，不必在每个插件里重新实现装备字典定位、原生事件挂钩、保存同步、菜单线程和插件数据隔离。

当前游戏适配针对 Steam Windows x64《星界战士》2.6.4 的精确 EXE 指纹和单人模式。服务可用性以能力位和查询返回状态为准；不支持的游戏版本不能进行受控修改。

## 从两个完整示例开始

`mods/build_selector` 使用公开 SDK 和可选的 `menu.hpp`：F10 打开窗口，搜索 355 个光环、38 个通用技能，选择目标槽位，应用草稿，保存和载入插件自有构筑预设。菜单无需 d3d11 加载入口，也不需要开启渲染回调。源码可作为自选内容、挑战配装或奖励菜单的起点。

`mods/event_responder` 使用公开原生事件流：当前本轮受到伤害后提交回血请求，拾取水晶后提交法力补充请求；每个响应等待结果，不因重复采样重复发奖。源码可作为受击触发、拾取奖励和挑战进度的起点。事件去重、游标溢出与场景变化仍需由插件按自身规则处理。

示例默认禁用。先在可写的 SDK 目录编译，安装时启用自己的测试副本，保留独立的测试存档。安装器不会替你启用示例或建立存档隔离。

```powershell
./tools/build-mod.ps1 -ModDirectory ./mods/build_selector
./tools/build-mod.ps1 -ModDirectory ./mods/event_responder
# 安装框架后，将所选示例目录中的 DLL 和 mod.json 复制到
# 游戏目录的 aamod/mods/<插件目录>，在该副本设置 enabled 为 true。
./tools/launch-game.ps1 -GameDir '<游戏安装目录>' -Commands -GameplayEvents
```

编译插件需要 PowerShell 7 与 Visual Studio C++ Build Tools。完整源码构建还需要 Python 3.11+；运行时需要对应的 x64 Visual C++ 运行库。详见[开发者起步](开发者起步.md)与[试用版交付流程](试用版交付流程.md)。

## 实现自己的内容规则

1. 在 `AAMOD_Init` 检查 API 尺寸及能力，再保存函数表。不要把当前 328 字节完整结构作为所有旧宿主的必然前提。
2. 用 `game_state`、`equipment`、`combat_state` 读取一致的当前场景纪元和装备；从 `content_catalog` 选择允许的内容 ID。
3. 用 `equipment_submit` 提交槽位、目标 ID、预期旧 ID 与纪元。用 `equipment_result` 等待应用、冲突、过期或失败结果；不要直接写内存，也不要因等待保存而重放请求。
4. 若请求检查点保存，`SAVE_DISPATCHED` 只表示原生保存已派发。游戏文件实际落盘与跨进程恢复需要单独验收。插件构筑预设通过 `data_write/data_read` 保存，与游戏检查点是两件事。
5. 用 `gameplay_events` 获取伤害、水晶拾取、开局与结束事件。`state_events` 是快照差分，不能替代原生事件。结束需区分败局、胜利和放弃；保存进度后返回主菜单不表示结束本轮。
6. 工作线程、菜单线程与回调资源必须在卸载时结束。公共契约、资源限制和错误码见[SDK 稳定规则](SDK稳定规则.md)。

## 当前扩展边界

技能服务替换现有四槽中的通用技能；不是新法术脚本引擎，也不提供签名技能选择、任意等级或冷却写入。光环服务复用游戏已有内容。自定义规则、奖励频率与组合效果由插件实现。

资源服务支持插件自有 PNG 解码、所有者管理和受控原生图片替换。保留字段 asset_register 尚不可用。它没有提供任意地图、敌人、动画或音频注入的通用接口。默认不启用实验修改、原生事件或渲染；仅为实际需要的插件打开对应能力。

本阶段按少量 C/C++ 开发者试用交付。多人模式、高 DPI、所有房间与内容组合、其他 EXE 版本仍需扩充认证后再承诺兼容。
