# 开发者预览：起步与能力边界

目标为《星界战士》Steam Windows x64 2.6.4。当前为 0.1.9-dev 小范围开发者试用，公开 API 为 328 字节并保留 ABI 1 旧前缀。内容开发与两个公开示例见[内容开发者快速开始](内容开发者快速开始.md)。已完成隔离存档下的 600 秒启动、正常进场、战斗与转场验收，以及原生图片可见替换、恢复和重复使用验收；这不是所有场景与设备的完整认证。

## 构建框架

安装 PowerShell 7、Visual Studio 2022 C++ Build Tools 与 Python 3.11+，在项目根执行：

```powershell
./build.ps1 -Test -PythonPath '<真实 python.exe 路径>'
```

构建直接通过 Developer PowerShell 调用 MSVC，测试使用独立隐藏窗口，不启动游戏。`out/test` 是模拟游戏目录，测试结果不能证明游戏兼容性。

## 创建插件

复制 `mods/template` 为自己的目录，修改 mod.json 的 id、name、version、entry 和源码中的消息，然后执行：

```powershell
./tools/build-mod.ps1 -ModDirectory ./mods/template
```

将生成的 DLL 与 mod.json 一起放到 `aamod/mods/<id>`。插件提供 `AAMOD_Init`，可以提供 `AAMOD_Shutdown`。先用独立 host 验证，再在测试存档中验证游戏行为。

## 安装与启动

```powershell
./install.ps1 -GameDir '<游戏目录>' -WhatIf
./install.ps1 -GameDir '<游戏目录>'       # 默认 winmm 入口、关闭渲染挂钩
./tools/launch-game.ps1 -GameDir '<游戏目录>'
./install.ps1 -GameDir '<游戏目录>' -Uninstall
```

安装器拒绝覆盖未知加载器，升级前校验旧清单与构建产物，失败回滚；卸载保留插件、配置与日志。游戏目录需要写权限，本预览未提供自动 UAC 提权入口，权限拒绝会清晰报错。另一个 Steam 库须显式指定目录。更换入口前先卸载当前入口。

需要帧回调时，使用 `-Shim d3d11` 安装，并通过 `launch-game.ps1 -Render` 启动；渲染由子进程环境 `AAMOD_RENDER=1` 显式开启。直接从 Steam 启动默认不安装渲染挂钩。`version.dll` 入口已从安装选择中移除，避免与现有 BD 加载器争用。

## 公共契约

- ABI 1 的原 128 字节及 208 字节前缀保持原位，当前开发结构为 328 字节。新增字段只能追加；使用前检查入参 size、api_version、api_size。
- `AAMOD_API_HAS(api, capabilities)` 为真时才能读取 capabilities；旧核心没有该字段。
- capabilities 报告已实现的服务。HOOKS、ANCHORS、FRAMES、GAME_INFO、GAME_STATE、状态差分 EVENTS、PNG ASSETS 已实现。精确游戏适配成功后提供 NATIVE_IMAGES；COMMANDS 默认关闭，通过 launch-game.ps1 -Commands 显式开启。本阶段增加 PLUGIN_DATA、CONTENT_CATALOG 和装备/资源查询；开启命令后提供受控装备操作。`-GameplayEvents` 单独开启原生事件适配，种类范围由查询结果的 supported_kinds 决定。插件应检查能力位而非硬编码数值。FRAMES 不保证渲染挂钩已经生效或兼容当前游戏。
- 公共头支持 C 与 C++。插件返回非零初始化结果时，核心清理本模块的帧订阅与 hook，再卸载；插件仍须在失败返回前结束自有工作线程并清理其他自有资源。
- 帧回调在渲染线程执行，保持短小，不做磁盘、网络或耗时逆向；渲染帧不是游戏逻辑更新事件。
- 配置加载后不可变。已存在配置字符串借用指针可保持到核心关闭；传入默认值的内存仍由调用者负责。
- 原生 DLL 的回调与 detour 按其代码所属模块归属。初始化失败或退出时，核心移除其帧订阅与挂钩，清理失败则保留模块，避免跳入已卸载代码。JIT、动态生成代码或共享辅助 DLL 的归属尚不支持；当前只认证 C/C++ 原生 DLL。
- 退出时不在 DllMain 内调用插件清理。进程退出由系统回收；宿主需显式清理时，先停止渲染/游戏循环并结束插件工作线程，再从普通控制线程调用 `AAMOD_ShutdownCore`。禁止从帧回调、DllMain 或初始化回调调用关闭接口；不支持热重载。
- 原生插件拥有进程内权限，不是安全沙箱；第三方插件必须来自可信作者。

## 当前限制

提供 hello、最小模板、身份诊断、只读状态、状态事件和自有 PNG 资源示例；受控回血示例默认关闭，已通过单人战斗一次恢复与过期请求拒绝的实机增量验收，完整矩阵仍待覆盖。尚无伤害统计或训练模式等成品插件。原生图片替换已经开放，见 [原生图片替换接口](原生图片替换接口.md)，包含默认关闭的 native_image_sample 及自有测试 PNG。构筑查询、目录、插件持久数据与共享菜单已加入开发版本，见《内容开发闭环》；六功能交付仍未完成。稳定房间 ID 与 Lua 尚未开放。完整 JSON schema、插件依赖与冲突解析和持续集成仍在后续范围。最新接管计划见 `接管与路线图.md`。


身份查询契约和诊断插件见 [游戏适配层](游戏适配层.md)。


离线插件加载可使用 tools/test-mod.ps1，不依赖游戏或 GPU。完整交付路径见《试用版交付流程》，版本和兼容声明见《SDK稳定规则》。


## 内容开发示例（0.1.9 开发阶段）

- `data_sample`：自有数据读写与重启恢复；逻辑键位于插件命名空间。
- `equipment_watch`：复制当前五个光环槽、四个通用技能槽。
- `content_smoke`：目录、光环效果、技能替换与法力补充的操作验收。
- `build_selector`：公开 SDK + 可选 `menu.hpp`，F10 打开目录搜索与构筑预设菜单，Esc 释放后关闭。当前本轮应用；预设是插件自有数据，未包含符文。需 `-Commands`。
- `native_event_watch`、`event_responder`：原生来源记录与受控响应；需 `-GameplayEvents`，响应还需 `-Commands`。拾取/结束适配和完整响应实机验收尚未完成，见《原生玩法事件接口》。

可修改内容的示例默认禁用，开发者在自己的安装副本中启用所需插件。`menu.hpp` 使用原生 Unicode 控件，在插件线程中运行；关闭时必须等待该线程，公共 C ABI 不传递 C++ 对象。
