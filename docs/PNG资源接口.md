# 插件自有 PNG 资源

`resource_owner` 为插件根目录的核心 token。`image_load` 接受相对该目录的 UTF-8 文件路径，解码为不可变、保留原始 alpha 的 RGBA8 像素。每次加载返回独立资源句柄、宽高、步长和字节数；插件可以据此创建自己的渲染纹理或其他效果资源。示例 `mods/image_sample` 使用项目自制棋盘图，不包含游戏图片。

同步解码应在初始化或工作线程执行，不在渲染回调中阻塞。返回的像素指针是核心持有的资源内存，不是游戏对象地址；它在显式释放或插件清理前有效。读取与释放由插件协调，不能读取已释放指针。重复释放和跨插件释放明确失败。核心在插件关闭线程与回调后清理遗留图片；初始化失败时回滚其资源，挂钩清理失败而被保留的模块同时保留资源，避免仍存活代码读到已释放内存。

绝对路径、目录跳出、ADS、无效 UTF-8 和解析后位于插件根目录外的链接均被拒绝。文件从已经核验的句柄读入；WIC 从该内存解码，不再次按路径打开文件。编码文件最多 32 MiB，每轴最多 8192 像素，解码最多 64 MiB。每插件最多 16 张、64 MiB，全部插件保留像素最多 256 MiB。失败不改调用者输出，错误区分路径、文件 I/O、格式、限额、句柄、COM 和内存不足。

当前能力位是 `AAMOD_CAP_PNG_RESOURCES`。原预留 `asset_register` 和 `AAMOD_CAP_ASSETS` 仍未开放：本接口不会替换游戏原生图片。WIC 流的输入内存在全部解码 COM 对象释放前保持有效，像素转换采用微软的 RGBA8 纹理加载流程。[WIC 内存流契约](https://learn.microsoft.com/en-us/windows/win32/api/wincodec/nf-wincodec-iwicstream-initializefrommemory)、[微软纹理加载示例](https://learn.microsoft.com/en-us/windows/win32/direct3d11/overviews-direct3d-11-resources-textures-how-to)。

## 原生图片扩展的研究边界

已确认当前精确 EXE 的 Assets.dat 分组索引、图片 ID 到文件偏移的寻址、图片几何头、原生压缩数据加载，以及另一条外部图片解码路径。图片组有 71870 个索引；这来自原生初始化器读取的索引字节数，不是根据整个文件大小猜测。`tools/image-bank-info.py` 只输出指定图片的几何与记录长度，要求匹配 EXE 指纹，不提取或修改游戏图片。

这些静态证据尚未证明运行中的替换、纹理缓存刷新、所有权与释放闭环。原生替换须后续隔离实机验证，不提前挂钩、不开放占位能力。PNG 服务的离线契约覆盖 RGBA/RGB/灰度/索引透明图、中文路径、越界链接、损坏与非 PNG、尺寸及编码限额、重复/跨插件释放、并发加载、STA/MTA 和插件回滚；不等于已验证游戏原生图片替换。

开发者可先使用 [原生图片替换计划](原生图片替换计划.md) 准备并复核图片 ID 与自有 PNG 的绑定。计划工具只做离线检查，当前要求同逻辑尺寸、非交错 RGBA8；不改变本接口或开启原生替换能力。
