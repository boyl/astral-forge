# 只读状态接口（开发中）

0.1.4-dev 在 C ABI 1 末尾追加 `game_state`，偏移 144，当时 API 总长 152 字节。0.1.5-dev 继续追加事件、命令和 PNG 资源成员，总长 208 字节；旧字段保持原位。`AAMOD_CAP_GAME_STATE` 表示查询服务存在；具体宿主是否可采样由快照 `status` 判断。

## 边界与使用

加载核心依赖 `game_state` 适配器，适配器依赖精确的 `game_profile` 身份；插件只依赖公开头 `aamod/aamod.h`。渲染模块不参与状态采样。沿用已有加载核心架构，未增加 UI。

快照为 256 字节，玩家结构为 40 字节。`game_state` 可从插件工作线程查询，以读写锁复制完整快照；没有借用指针、对象地址或跨帧对象句柄。空指针、短缓冲区返回参数错误且不写入；长缓冲区的多余尾部保留。

```cpp
if (AAMOD_API_HAS(api, game_state) && api->game_state) {
    AAModGameState state = {};
    if (api->game_state(&state, sizeof(state)) == AAMOD_OK &&
        state.status == AAMOD_STATE_READY && state.players[0].present &&
        (state.players[0].valid_fields & AAMOD_PLAYER_POSITION)) {
        // 此次采样的 P1 碰撞对象层内坐标。
        double x = state.players[0].layer_x;
    }
}
```

- UNSUPPORTED：未知可执行文件，不安装游戏更新钩子。
- WAITING：精确身份匹配，等待原生帧对象构造及首次采样。
- READY：拥有完整采样；菜单等场景中没有玩家是正常结果。
- FAULT：构造未在限定时间内出现、钩子冲突、更新线程变化或外部布局失效。清空旧玩家与场景，停止采样，不自动重试。
- STOPPED：核心显式关闭，清空缓存。

`sequence` 是更新边界采样计数，独立于 Present；`update_thread_id` 为首次采样时固定的游戏线程。`sampled_at_ms` 使用系统启动后的单调毫秒计数，查询者可用它判断快照年龄。暂停、失焦时可能保留最近一次完整快照，不能把查询频率当作游戏更新频率。

`scene_index` / `scene_name` 表示引擎 layout，例如 `layout_mainMenu`、`layout_hub`、`layout_game`，不能用来识别关卡内的程序生成房间。`scene_epoch` 在 layout 改变或原生循环计数回退时递增；它不是战斗次数或房间编号，同 layout 内的任意对象复用也不保证引起递增。

每次采样重新遍历引擎层对象链，在当前有效链中寻找 P1/P2 碰撞对象，复制坐标；玩家消失后下一次完整采样的 `present=0`，其全部数据为零。坐标是原生层空间，尚未承诺屏幕坐标或统一世界坐标。没有暴露引擎对象 UID，因为对象池可能复用它。

血量字段已依据游戏原生 `gameProgress` 绑定定位，并使用隔离存档的四个独立值（P1 173/231、P2 98/419）核对运行时加载结果。大厅初始化会将血量重新设为游戏的默认值；快照报告实际采样值，不复用存档中的初始值。

只有玩家碰撞对象存在且当前最大血量大于零时，才置 `AAMOD_PLAYER_HEALTH` 并提供 `health/max_health`。最大血量为零时，该字段尚不可用；非有限数值或负最大血量视为适配失效并停止采样。未置有效位时，结构内零值没有血量语义。`present` 仅表示对象存在，不表示玩家存活；死亡动画期间对象可能仍存在，血量可能为零或负值，接口保留原生读数。

## 生命周期

适配器只对已验证的 Steam Windows x64 2.6.4 完整文件指纹启用。独立工作线程等待静态 Frames 构造，以原子比较交换替换该实例的五槽虚表副本；原生事件处理后的虚函数先调用原函数，再在同一游戏更新线程读取数据。只读查询本身不修改玩家、存档、渲染设置或游戏流程；默认关闭的实验命令遵循独立的受控修改契约。

显式 `AAMOD_ShutdownCore` 必须在游戏与渲染线程静止的边界调用。适配器停止并等待自己的工作线程，只在实例虚表仍属于自己时还原；不支持运行中卸载或热重载。插件关闭自身工作线程后才能释放 API。

## 独立示例

`mods/state_watch` 仅包含公开 SDK 头。用 PowerShell 7 执行：

```powershell
./tools/build-mod.ps1 -ModDirectory ./mods/state_watch
```

将编译后的 `state_watch.dll` 与 `mod.json` 放到插件发现目录。示例每 250 毫秒查询缓存，在可用状态、场景 epoch、玩家存在性、字段可用性或血量改变时输出日志；不写存档、不安装游戏钩子、不依赖 BD Mod。工作线程在 `AAMOD_Shutdown` 中停止并等待。

## 验证边界

离线契约覆盖菜单无玩家、在第 84 层的玩家、玩家移除、同 layout 计数回退、无效场景、损坏链、未知状态、短缓冲区拒绝、尾部保留和故障清空。它们验证内存边界，不替代游戏游玩验收。

实机正常菜单、索瓦开局、生成场景及战斗房间切换、敌人攻击致死、结算返回大厅和再次开局已通过。截图及独立只读观察器核对流程，公开 state_watch 记录对应场景 epoch 和血量变化。完整覆盖及主动结束测试的边界见《阶段验收》。本版本仍为开发预览，程序生成房间的稳定 ID、双人实机及所有地图未开放或全量验证。
