# 游戏更新维护

## 工具用途

游戏更新后，先确认原生契约是否仍成立，再修复失效适配，最后对同一候选进行隔离实机验收。维护工具保留本次游戏、核心和扫描器的哈希用于证据关联；版本号和整文件哈希不参与能力白名单。

工具位于源码仓库，需要 Windows x64、PowerShell 7、Python 3.11+ 和 Visual Studio C++ Build Tools。只读扫描器直接复用 `src/core/game_layout.cpp`，避免维护第二份定位算法。扫描使用 `DONT_RESOLVE_DLL_REFERENCES` 映射 EXE，不解析导入、不调用游戏入口。`tools/build-maintenance.ps1` 只构建维护程序，不重建已验收的核心 DLL。

| 工具 | 输入 | 输出与副作用 |
| --- | --- | --- |
| `maintain-update.py scan` | 游戏目录、候选核心、扫描器 | 静态契约、RVA、字段、三项指纹；不启动游戏 |
| `compare` | 前后两轮扫描 | 能力退化/恢复、RVA 与字段变化；没有版本限制 |
| `init` | 本轮扫描 | 11 个必需项全部为 `pending` 的验收计划 |
| `record` | 上一份计划、观察、证据和实际候选哈希 | 新计划，追加证据；不覆盖原计划 |
| `finish` | 已填写计划 | 复核必需项、候选身份与证据文件当前哈希 |
| `save-baseline` / `save-verify` | 真实存档目录/本轮基线 | 只读核对新增、删除、内容变化；不恢复或写入存档 |
| `maintenance.snapshot_io` | 私有探针快照路径 | Windows 原子交换，跨进程锁、允许文件替换的读句柄 |

这些工具不控制键鼠、不上传、不自动部署，也不把“定位成功”视为“玩法正常”。游戏专用场景输入仍使用受限隔离脚本；BD 输入工具由维护者独立配置，不复制进框架。

## 1. 建立更新轮次

在仓库根目录的 PowerShell 7 中运行。替换示例路径；维护产物放在忽略的 `out` 下，不能放入游戏或受保护存档目录。

```powershell
$Python = '你的 Python 3.11+ 可执行文件'
$Game = '包含 Astral Ascent.exe 的游戏目录'
$Round = './out/update/本轮唯一名称'
New-Item -ItemType Directory -Path $Round -ErrorAction Stop
./tools/build-maintenance.ps1
& $Python ./tools/maintain-update.py scan --game-directory $Game --output "$Round/scan.json"
& $Python ./tools/maintain-update.py init --scan "$Round/scan.json" --output "$Round/plan-00.json"
```

可以用 `--core` 指定实际准备验收的核心，用 `--probe` 指定独立构建的扫描器。扫描时三份文件前后指纹必须一致。报告不证明文件已安装或核心已加载，实机日志仍需另行证明加载的 DLL 就是该候选。

扫描输出 `contracts-incomplete` 时退出码为 2，并保留部分报告供排障。无法映射、无效报告或输入变化同样返回 2，不能继续当作通过。输出文件已存在时拒绝覆盖。

## 2. 比较与修复

保留上一轮的扫描报告，再与本轮比较：

```powershell
& $Python ./tools/maintain-update.py compare --before '上一轮 scan.json' --after "$Round/scan.json" --output "$Round/diff.json"
```

`gameChanged` 是游戏文件变化，`regressions` 才表示此前存在的原生契约失效。RVA 或字段偏移移动但全部契约仍成立时，仍需实机回归，不添加版本号硬限制。失效时在 `src/core/game_layout*`、`native_*_patterns.h` 和对应契约测试中定位根因；保留唯一匹配、函数边界、调用关系与字段约束，不把旧 RVA 直接写死。

修改适配源码或候选核心后重新构建，并重新扫描、创建新计划。扫描器必须由本轮源码构建，不能用旧扫描器判断新适配代码。不得把上一候选的实机记录复制成新候选通过。

```powershell
./build.ps1 -Test -PythonPath $Python
./tests/run-maintenance.ps1 -PythonPath $Python
```

## 3. 隔离实机与存档保护

每次测试开始前，重新对实际存档目录建立基线。旧轮次的基线不能替代本次开始时的状态。禁止把游戏、存档和本机绝对路径提交到仓库。

```powershell
& $Python ./tools/maintain-update.py save-baseline --directory '本机真实存档目录' --output "$Round/save-before.json"
# 运行经过核查的隔离脚本；证明 SavedGames 重定向已生效，才允许输入。
& $Python ./tools/maintain-update.py save-verify --baseline "$Round/save-before.json" --output "$Round/save-after.json"
```

核对目录完整文件集合，新增、删除、内容变化都返回 2。清单含链接或越界相对路径时拒绝处理；工具不覆盖存档。其他真实游戏进程也可能造成存档变化，失败时先判断来源。

实机脚本应记录目标 EXE 与实际加载核心的哈希、自己启动的 PID、隔离门禁、状态变化、原生事件、操作结果、关键截图和退出时存档核对。每次输入确认目标窗口与 PID，结束时释放输入并关闭自己的隔离进程。地图、菜单、IME、镜头或 Boss 阶段变化需要重新核查场景前提，不能只照搬本轮坐标。

快照交换可在外部脚本中通过显式加入仓库 `tools` 路径后导入：

```python
from maintenance.snapshot_io import publish_snapshot, read_snapshot
publish_snapshot(snapshot_path, json_text)
observation = json.loads(read_snapshot(snapshot_path))
```

读写双方都使用模块。锁默认等待 2 秒；仅对外部查看器已观察到的 Windows 错误 5/32 有最多 200 ms 的替换等待，其他错误直接失败。不要在运行时用禁止删除共享的查看器持续打开快照文件。本模块仅支持 Windows。

## 4. 记录证据与完成判定

每项可以重复 `record` 添加 JSON、日志和截图，每次输出一个新计划。必须用实际观察对应的游戏和核心哈希，不能只把计划中的值复制过去当作加载证明。示例记录静态定位项：

```powershell
$Scan = Get-Content "$Round/scan.json" -Raw | ConvertFrom-Json
& $Python ./tools/maintain-update.py record --plan "$Round/plan-00.json" --id offline.contracts --status passed --kind offline --evidence "$Round/scan.json" --game-sha256 $Scan.gameSha256 --core-sha256 $Scan.coreSha256 --observation '本轮扫描定位全部原生契约' --output "$Round/plan-01.json"
# 按计划中每个 criterion 完成观察，依次记录；未验证就记录 unverified，失败记录 failed。
& $Python ./tools/maintain-update.py finish --plan "$Round/最终计划.json" --output "$Round/summary.json"
```

11 项覆盖离线契约/回归、实机启动、光环与普通技能、回血补法、水晶拾取、三种原生结局、预设、检查点持久化、资源可见效果和存档保护。删除必需项、更改标准、用离线或模拟证据填实机项、混用候选、证据丢失或漂移，都不能完成。未完成的汇总仍会保存，退出码 2；完整时退出码 0。

记录明确标为 `maintainer-attestation`：维护者对观察负责。文件指纹约束保证记录关联及未漂移，不能鉴定日志真实性或代替语义判断。历史验收、模拟和未来版本始终分开；多人、控制器、图形设备重建等范围不因清单通过自动获得认证。

## 5. 交付与收尾

只有本轮必需验收完成后，再更新兼容文档、按正式打包工具生成制品并审计，提交、推送和核对远端 SHA。新的维护工具自动进入源码包，当前运行包不包含需要核心源码编译的扫描器。

本地计划可能含证据绝对路径，存档基线含个人目录与文件名。保留在 `out` 或外部私有证据目录；公开验收文档只摘录去除个人信息后的结果。保留正式包、回滚包、必要证据、可复用夹具；临时解压副本和一次性诊断产物在完成后按明确路径清理，不用宽泛规则清空未知目录。
