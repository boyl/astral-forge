# 原生玩法事件接口（试用）

本接口追加在 328 字节 API 尾部，与原有快照差分流 `state_events` 分开。快照变化不能作为拾取或受击的原生来源。当前游戏适配精确绑定 Steam Windows x64 2.6.4 的已审核指纹；默认关闭，使用 `tools/launch-game.ps1 -GameplayEvents` 后，子进程设置 `AAMOD_EXPERIMENTAL_EVENTS=1` 才安装观察入口。事件响应示例还需要 `-Commands`。

`AAMOD_CAP_GAMEPLAY_EVENTS` 表示原生事件适配器可用。查询返回的 `supported_kinds` 才表示本次安装了哪些来源；这个支持位不是实机认证结果。当前安装开局、受击、水晶拾取和本轮结束观察；败局、菜单主动放弃与完整二阶段/片尾后的胜利均已通过隔离单人实机验收；保存退出负例也已通过。开发者必须检查支持位并遵守各来源的认证范围。

调用 `gameplay_events(after, events, capacity, sizeof(AAModGameplayEvent), &count, &info, sizeof(info))` 复制事件。传 `capacity=0` 可只读取边界；首次订阅可将游标设为 `info.newest`，避免把加载之前的历史当成新事件。读取成功后推进到最后一条记录的 `id`。

环形记录保留最近 128 条。历史过期或未来游标返回 `AAMOD_ERR_EVENT_CURSOR`，`count=0`，事件缓冲不改变，`info` 提供最新边界。调用者应明确提示丢失历史并选择新游标，不无条件重放旧动作。无效参数不改输出。接口复制数据且不保留插件回调，可从工作线程查询。

每条记录包含编号、种类、玩家、来源 RVA、原生执行线程、引擎本轮计数、时间及来源相关数值。玩家从零开始；当前受击只覆盖 P1 单人活跃本轮。`run_key` 是引擎计数，不能当作跨进程唯一标识。没有原生来源证据的内容 ID 等字段保持零。

| 种类 | 原生来源 | 字段含义 | 实机状态 |
| --- | --- | --- | --- |
| RUN_START | `0x31ddff0` 执行完成 | `run_key` 为本轮计数 | 正常开局、独立原生计数一致；线程事务修复后复测通过 |
| DAMAGE | `0x311fbf1` 普通命中调用原生生命提交 | `before/after` 为该调用边界生命，`amount=before-after` | 普通敌人实机命中通过；独立生命值一致；菜单光环修改不误报伤害 |
| PICKUP | `0x200ae00` 原生近距离水晶收集函数 | 实时水晶量及增量；`content_kind=3`、`content_id=1` | 正常拾取与独立实时水晶量实机通过；SDK 法力上限截断及非满法力 5→6、独立法力读取均通过 |
| RUN_END（败局） | `0x3505770` 原生败局包装函数 | `content_kind=4`、`content_id=0` | 实际生命归零、lastRunState=0、同线程唯一事件通过 |
| RUN_END（胜利） | `0x35057b0` 原生胜利包装函数 | `content_kind=4`、`content_id=1` | 二阶段、片尾与后续过场后的唯一事件、lastRunState=1、实际保存链通过；隔离 Boss 生命夹具 |
| RUN_END（放弃） | `0x15a8b80` 的已确认菜单调用 | `content_kind=4`、`content_id=2` | 正常菜单确认、续局删除和唯一事件通过；保存退出不发布结束 |

菜单主动放弃使用原生续局删除入口 `0x15a8b80`，只观察已确认返回地址 `0x1d5ed9f`。该函数同样由败局调用，其他调用必须转发而不发布主动放弃。`content_kind=4`、`content_id=2` 表示主动放弃；事件在原生入口执行完成后发布。隔离实机验收 45 用正常 S 菜单导航及确认键触发，事件线程与独立实际保存调用链一致，返回主菜单且隔离续局记录删除；暂停及未确认菜单不发布事件，每轮仅一次。保存续局后退出的实机排除行为已在验收 53 通过，见下文。

胜利适配使用原生包装入口 `0x35057b0`，保留 RCX 帧、XMM1 双精度结果及 XMM0 返回值；仅接收原生胜利调用位置及结果 1。`content_kind=4`、`content_id=1` 表示胜利。该适配通过 ABI 与边界离线测试及隔离实机验收 62：完成两个 Boss 阶段、制作人员名单和后续过场，返回原生结算后只发布一次胜利事件，独立原生 lastRunState=1 与保存调用链一致。该测试按用户授权将隔离 Boss 当前生命降至 1，再以正常攻击触发原生阶段转换；它验证胜利来源和结算生命周期，不认证普通战斗平衡。过场长按 R 3 秒跳过；制作人员名单按原生提示用 C，后续过场仍长按 R。

伤害入口复用 RCX 帧参数的原生派发器 `0x14b8a20`，仅接收返回地址 `0x311fbf6` 的调用，并检查原生操作上下文；其他统计修正、整数化、菜单或插件调用不产生伤害记录。普通命中上层函数还接受 RDX 对象参数，不能当作帧参数单参函数挂钩。原生函数总是先执行自身行为，观察不改变参数或返回值。受击记录排除回血、P2、双人、未就绪、非有限数值及已经死亡的输入。原生提交值可能先于 HUD 或后续修正；响应命令应重新查询当前状态，并用当前场景纪元提交，由受控命令执行端检查死亡、过期和上限。

`native_event_watch` 仅记录来源和数值。`event_responder` 仅使用公开 SDK：伤害后按损失量请求回血，拾取后请求补充一点法力；它只响应实际流中存在的种类，未接入拾取时不会模拟触发。示例从加载时最新游标开始，忽略过旧事件，每次保留一个待执行请求，记录执行结果。该示例已编译，并通过过旧事件、支持位、P2、死亡、双人、场景/状态、游标过期及单请求并发的离线行为测试；正常敌人伤害→公开订阅→受控回血的实机闭环已通过，回血按当前上限截断；水晶拾取响应已通过 5→6 的真实法力增加及独立读取验收，默认禁用。

停止观察先停发布，再以线程事务移除入口。已进入的调用仍可通过保留到进程结束的跳板转发原函数；核心模块不在这里卸载。原生插件作者仍需在自己的卸载回调中停止并等待工作线程。







水晶适配保留 RCX 帧、RDX 玩家和 R8 收集物三个参数，仅观察返回地址 `0x200ade2` 的近距离收集调用，排除其他资源奖励及消费入口。实时水晶位于帧字段 `0x1c3f30`；保存字典中的水晶量不是实时收集状态。只在确认 P1、单人、本轮不变且原生调用后资源增加时发布。该条目尚未证明其他货币或其他拾取物。



### 保存退出负例

隔离实机验收 53 通过正常暂停菜单选择“保存进度并退出”，返回原生主菜单（scene 282），实际续局及四技能 ID 保留，未发布 RUN_END。这里的退出是离开本轮返回菜单，游戏进程仍运行；不把菜单切换或存档写入当作本轮结束。
