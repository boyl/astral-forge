# SDK 稳定规则与试用边界

当前为 0.1.9-dev 小范围开发者试用；0.1.8-dev 保留为历史交付基线。功能认证以本版本附带的验收矩阵与证据为准。架构按长期多人使用设计，不承诺已经完成大规模兼容认证。

## 兼容规则

Windows x64 的 ABI 1 保持字段位置，只追加字段。0.1.8 的 AAModAPI 为 248 字节，0.1.9 开发候选追加至 328 字节，原 128/208/248 字节前缀保留；冻结旧头布局的二进制插件参与实际加载及关闭测试。插件先检查 AAMOD_Init 的 size 和 api_version，再检查 AAMOD_API_HAS 和对应能力位。能力位表示服务存在，不表示渲染回调已经启用或任意游戏版本已认证。原生事件的 supported_kinds 描述实际安装来源，开局、伤害、水晶拾取及败局/胜利/放弃的实际认证范围以接口文档为准；保存后返回主菜单不发布本轮结束。

需要改变旧字段含义、布局或调用约定时发布新的 ABI 主版本，不静默破坏 ABI 1。预览期可调整实验功能，但必须记入 CHANGELOG；已发布的 ABI 1 字段仍不得重排。弃用接口先记录替代方式，在同一 ABI 内保留旧入口。版本升级先备份并用隔离存档验收，安装器只升级清单中未漂移的框架文件。

## 接口等级

| 等级 | 当前接口 | 承诺与使用限制 |
|---|---|---|
| 基础契约 | 日志、配置、核心内存、加载、大小检查 | ABI 1 前缀保持兼容；插件自己的线程必须由插件收尾 |
| 预览服务 | PNG 解码、只读游戏身份、状态差分轮询、插件命名空间数据 | 公开契约与失败结果有测试；游戏状态依赖精确适配，不是通用房间/伤害语义 |
| 实验适配 | 原生图片替换、装备与内容目录、受控回血/法力/装备修改、原生玩法事件、原生 hook、可选帧回调 | 精确游戏版本与指定场景验证；回血和渲染必须显式开启，变更示例默认禁用 |
| 保留字段 | asset_register、event_subscribe | 不可用；不要因为有函数指针就调用或把它们当作 PNG/状态事件接口 |

GAME_STATE 表示可查询服务，未知宿主返回不支持状态。NATIVE_IMAGES、COMMANDS 只在适配成功且相应条件成立时报告。未知游戏 EXE 不安装游戏专用挂钩，不执行受控命令；基础加载器仍可用于诊断。

## 插件兼容声明

新的插件清单建议符合 schemas/mod.schema.json，并声明：

```json
{
  "id": "my_image_mod",
  "entry": "my_image_mod.dll",
  "enabled": false,
  "api_version": 1,
  "min_api_size": 248,
  "required_capabilities": 1024
}
```

api_version 不匹配、min_api_size 超出核心大小或缺少任何 required_capabilities 时，核心在 LoadLibrary 之前拒绝，因此连 DllMain 都不执行。三个声明必须是范围内的非负整数且不能重复；api_version 大于零，min_api_size 不小于 128。能力位通过按位或组合，缺失的可选服务不要放入 required_capabilities，而应由插件检查后给出说明或禁用对应功能。

旧清单未声明时按 ABI 1、128 字节、无必需能力处理；旧插件仍负责自己的大小检查。运行时保留旧清单的宽松解析行为，只严格校验上述新声明；JSON schema 面向新插件编写与交付，并不意味着加载器已实现完整 JSON schema 校验。priority 按降序、同优先级按 id 排序；重复 id 采用第一个扫描结果并记录忽略。尚无依赖解析器或安全沙箱。

## 线程和生命周期

- 配置初始化后不变，借用字符串不得释放；核心分配的内存由核心 free_ 释放。
- PNG pixels 为不可变借用缓冲，至 image_release 或所有者清理前有效。插件结束读者线程后才能释放。
- 状态与差分事件复制到调用者缓冲，适合工作线程轮询；过期游标必须明确处理丢失历史。
- 命令由工作线程提交，在游戏更新边界执行；记录结果与 scene_epoch，禁止用直接写游戏内存绕过命令契约。
- 图片替换提交复制 PNG 到核心，实际应用和恢复在原生上传边界执行。查询异步状态，不把提交成功等同于可见效果。
- 帧回调运行在渲染线程，保持短小。原生 hook 的安装/撤销要求调用方保证被修改代码没有并发执行；加载器不是任意并发注入的安全保证。
- 初始化成功后才激活可变更请求；失败撤销。关闭前撤销新请求，插件 Shutdown 结束自有线程，核心再清理资源。挂钩撤销失败保留仍被引用的模块和资源并记录错误。
- 显式 AAMOD_ShutdownCore 仅用于已停止游戏/渲染循环的宿主。禁止从 DllMain、初始化或帧回调调用，不支持热重载。游戏进程退出由系统回收，不承诺强制退出执行全部插件 Shutdown。

## 试用版支持范围

支持 Steam Windows x64 Astral Ascent 2.6.4、EXE SHA-256 ca376d2b741f65c75c416317517d24c316dd8a32a4eae6559030797b3b9aa88b。单人正常菜单/大厅/进场/战斗/转场和主菜单背景替换有实机记录；双人实机、全部地图、图形设备重置及所有原生图片尚未认证。不同 Steam 库通过 -GameDir 显式定位。

下一阶段的大规模门禁是外部开发者独立完成插件、双人和长期矩阵、依赖/冲突管理及可维护的真正游戏语义接口。试用版先收集实际缺口，不把未来门禁冒充本次已完成能力。
